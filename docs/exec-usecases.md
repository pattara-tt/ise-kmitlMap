# Use Case ฝ่ายบริหาร: ตรวจทานฉบับที่แนบมา

ฐานของเอกสารนี้คือ **ฉบับที่ผู้ใช้แนบมาล่าสุด** ทุกแถวบอกว่าข้อความในฉบับนั้นตรงกับระบบจริงหรือต้องแก้
อ้างอิงโค้ด: `components/panels/ExecPanel.jsx`, `components/ui.jsx`, `backend/src/server.js`

**สถานะ**
| ป้าย | ความหมาย |
|---|---|
| ✅ คงเดิม | ข้อความในฉบับที่แนบตรงกับระบบจริงแล้ว |
| ✏️ แก้เป็น | ข้อความในฉบับที่แนบถูก ~~ขีดฆ่า~~ แล้วตามด้วยข้อความที่ตรงความจริง |
| ➕ เพิ่ม | ฉบับที่แนบยังไม่มี แต่ต้องมี |
| 🗑️ ลบ | ลบทั้งขั้น (แยกไว้ในหัวข้อ "ที่ต้องลบ" ใต้ตารางของแต่ละ UC) |

**ทิศทาง**: → ฝ่ายบริหารทำ/สั่งระบบ · ← ระบบดึงข้อมูลหรือแสดงผล · (ว่าง) ระบบประมวลผลภายใน

## UC-2 ตรวจสอบข้อเสนอแนะและคำร้องจากผู้ใช้งานทั่วไป

## UC-3 ตรวจสอบบันทึกประวัติการแก้ไขข้อมูลแผนที่

| Participating Actors | ✅ คงเดิม | - |
| Actor's Goal | ✅ คงเดิม | ต้องการตรวจสอบบันทึกประวัติการปรับปรุงแก้ไขข้อมูลแผนที่ที่เปลี่ยนแปลงไปจากเดิมโดยผู้ดูแลข้อมูลสถานที่และอาคาร |
| Precondition 1 | ✅ คงเดิม | ผู้บริหารเข้าสู่ระบบด้วยสิทธิ์การเข้าถึงระดับบริหาร |

| Postcondition | ✅ คงเดิม | ประวัติการแก้ไขเปลี่ยนแปลงข้อมูลแผนที่ย้อนหลังถูกแสดงผลพร้อมรายละเอียดผู้แก้ไขและเวลาที่แก้ไขอย่างชัดเจน และรายการที่ข้อมูลต้นทางถูกลบไปแล้วยังคงแสดงอยู่ด้วยชื่อที่บันทึกไว้ |
